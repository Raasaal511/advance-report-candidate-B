# Отчёт по авансам договоров

CLI на Python: по выгрузке договоров, работ и платежей считает на выбранную дату, сколько уже выплачено и сколько осталось — **по каждой работе** и **итогами по договору**.

Задача из жизни бухгалтерии: авансы часто висят на договоре без привязки к работе, а смотреть нужно «за что уже рассчитались».

Контрольная дата из задания: **2026-11-10**.

---

## Быстрый старт

Нужен только Python 3.10+. Внешних зависимостей нет.

```bash
git clone git@github.com:Raasaal511/advance-report-candidate-B.git
cd advance-report-candidate-B

python3 report.py --date 2026-11-10 --data data
```

В терминал уйдёт полный отчёт. Чтобы сохранить CSV:

```bash
python3 report.py --date 2026-11-10 --data data --csv out/report-2026-11-10.csv
```

Готовый пример на контрольную дату лежит в `out/report-2026-11-10.csv` — можно сразу открыть в Excel / Google Sheets.

---

## Что делает программа

1. Читает три CSV из `data/` (формат описан в `data/FORMAT.md`).
2. На дату `--date` отбирает платежи, которые к этому дню реально «у подрядчика» (ушли и не вернулись).
3. Платежи с `work_id` сажает на работу; платежи без привязки разносит по работам договора.
4. Печатает отчёт и опционально пишет CSV.

Деньги считаются через `Decimal`, без `float`, до копейки.

## CLI

```text
python3 report.py --date YYYY-MM-DD [--data DIR] [--csv PATH]
```

| Аргумент | По умолчанию | Описание |
|----------|--------------|----------|
| `--date` | обязательный | Дата среза отчёта |
| `--data` | `data` | Папка с `contracts.csv`, `works.csv`, `payments.csv` |
| `--csv` | выкл. | Если указан — дополнительно сохранить табличный отчёт |

Примеры:

```bash
# контрольный прогон из задания
python3 report.py --date 2026-11-10 --data data

# другая дата
python3 report.py --date 2026-10-01 --data data --csv out/report-2026-10-01.csv
```

## Как читать результат

**По договору:** сумма договора, обязательства по работам на дату, выплачено, осталось оплатить.

**По работе:** `price` / `paid` / `left`, плюс статус на дату (`planned` / `done` / `cancelled`).

Кратко для бухгалтера: `ACCOUNTANT.md`.  
Все спорные правила и «что будет, если ошиблись»: `DECISIONS.md`.

Сжатый смысл правил по умолчанию:

- `queued` в «выплачено» не входит; `refunded` после даты возврата = 0
- отменённая работа: остаток к оплате 0
- аванс без `work_id`: сначала закрывает принятые работы (по дате приёмки), потом запланированные
